## 3. Почему переход оправдан: боли v0.0.41, которые 2.0 устраняет системно

1. **Монолит исчерпал ресурс патчуемости.** Каждая новая фича в v0.0.4x — это exact-substring патчи с assert'ами по количеству вхождений, борьба со скоупами esbuild (`ReferenceError: n is not defined` при вставке не в тот скоуп), два разных `var BAL` в одном бандле, мёртвые фасады (`dust-modal`, `meta-tree-modal`), 20+ наложенных слоёв `voronia-*`. Это работает, но цена каждого следующего шага растёт нелинейно.
2. **Доменная архитектура ТЗ (§3) закрывает наш исторический класс багов:** ResourceLedger + атомарные транзакции устраняют класс «частичного списания» (наш реальный баг v0.0.41: `spendGlobal`/`Et` не знал про compounds/rares), «двойных начислений» и гонок UI/симуляции (`syncCompact`, перезаписывающий нативный рендерер).
3. **Баланс уже наполовину вынесен.** `window.VORONIA_BALANCE` + инлайн-оверрайд v41 — это прото-конфигурация. В 2.0 она переезжает в версионированные JSON почти 1:1 (§3.1 «Балансные конфигурации отделены от кода» — у нас уже так).
4. **QA-контур масштабируется.** Наш harness (node + vm + DOM-заглушки, 16 секций) — костыль вокруг минифицированного бандла. Vitest + Playwright + parity-тесты (§16) дают то же самое надёжнее, а 16 секций harness'а становятся готовым списком сценариев для parity.
5. **3D-планета нового уровня (§5.1)** — LOD/instancing/frustum culling/quality presets/нормали от центра — в монолите с патчами это нереализуемо без переписывания рендер-слоя целиком; в модульной структуре это отдельный домен Renderer (read-only по правилам ТЗ).
6. **TypeScript strict** устраняет главный источник регрессий минифицированного кода: мы регулярно «угадывали» имена (`Et`, `Xp`, `Gx`…) по offsets. В 2.0 — типизированные контракты.

## 6. Рекомендуемый порядок работ (реалистичный план входа)

```
Треки параллельно:
  [PROD]  v0.0.41 — hotfixes по мере нужды (patch_v41*.py пайплайн сохранён)
  [DEV]   voronia2/ — новый проект по ТЗ

Этап 0  (1–2 сессии):  MECHANICS_CATALOG.md — реестр механик v0.0.41 с якорями
                       источника; список TO VERIFY (кривая LvScanGrowth, ветви
                       аномалий, боевые числа, полный каталог ресурсов);
                       golden-save + контрольные сценарии.
Этап 1  (2–3 сессии):  voronia2/ — Vite + TS strict, домены-заглушки с контрактами,
                       event bus, clock, конфиг-лоадер (импорт VORONIA_BALANCE),
                       CI-проверки (typecheck + vitest), ADR-001…003.
Этап 2–4:              Core → Economy (ResourceLedger) → Planets (seed-генератор)
                       → Scan; parity-тесты против v0.0.41 на golden-save.
Этап 5:                3D-прототип планеты (сфера → поли-сетка → граф соседства),
                       LOD/instancing, СРАЗУ замер FPS на целевом Android (R1).
Далее:                 по этапам ТЗ 6–15; v0.0.41 списывается только после G5.
```

Первый играбельный вертикальный срез («новая игра → скан → добыча → апгрейд → сохранение → загрузка») достижим до полноценного 3D — рендер на этапе среза может быть временным (2D-граф клеток), что ТЗ прямо разрешает (§14.1), при этом домены остаются чистыми.

## Постскриптум: решения приняты, Этап 0 выполнен (обновление вердикта)

**Решения владельца (2026-10-23):** платформа — паритет desktop+mobile (ADR-001); дистрибуция — модульный dist + single-file target (ADR-002); baseline миграции — v0.0.41 (ADR-003); старт — с Этапа 0.

**Этап 0 выполнен** (`voronia2/`): каталог механик (16 доменов, 65 якорей исходника, 18 фикстур runtime-извлечения, 10/10 шагов), golden-saves (fresh+midgame, version:39), сценарии GS-00…GS-14, TO VERIFY ×21, ADR-001…009.

**Ключевые факты извлечения (уточняют вердикт):**

1. Приложение A ТЗ подтверждено **11/11** (включая LvScanGrowth = clamp(techCostScaleMult, 1.03, 1.3), живое значение 1.15; окно «3 бесплатных скана после престижа»; science-формулу).
2. **Боевой раздел ТЗ (§9) устарел относительно baseline:** реестр `boss` v0.0.41 содержит strike-модель (удар 6±3с, лимит 30с, комбо ×0.1…×5), тиры стражей (sentinel/guardian/overlord, CD overlord = 3ч), потери 3–8 клеток (не 25%), восстановление 15 мин / 1800⚡ (не 30 мин / 250🔬+25💎). Предложение: источник истины = реестр v0.0.41 → **ADR-009 (ждёт утверждения)**.
3. Обнаружены системы, не описанные в ТЗ §4: weekly-циклы, 125 достижений, лор/финал, вселенные «Раскола» (`_shared`, `_u<N>`), ghost, cinematic, sonar, charge, boss-рейды → scope-вопрос Q2.
4. Найдена аномалия масштабирования рецептов (steel: базовые 1000⚡ против фактического спроса 10М⚡) → TV-21, блокирует parity крафта.
5. Сейв в storage — plain JSON; 💫 shards живут вне основного сейва (shared-слой вселенных) — важно для мигратора 2.0.
