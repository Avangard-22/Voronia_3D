# ADR-016 — Порт аномалий/зарядов/синтеза (Этап 4): границы дословности и отклонения

**Дата:** 2026-11-02 · **Статус:** принят · **Контекст:** Этап 4 (заряды жил, авто-surge, ветви аномалий, deep/tl, мутанты, синтез). Источник истины — золотой аудит 1.x `fixtures/stage4_audit_v0.0.41.json` (tools/extract_stage4.cjs, seed 20260401, NOW заморожен) и бандл (оффсеты в MECHANICS_CATALOG §I).

## Решения

1. **Причины отказов — закрытый набор 2.0.** 1.x возвращал строки `'destroyed'`/`'unexplored'` и пр.; 2.0 — `ActionResult` c reason из `REJECT_REASONS` (`type`/`state`/`cooldown`/`energy`/`cost`/`max`) + свободный `detail` (в detail сохраняется семантика 1.x). Поведение идентично, контракт строже.
2. **Выбор ветви — команда, не модалка.** 1.x `um()` — DOM-модалка c тостами; 2.0 — `chooseAnomalyBranch` (одноразовость: повтор → reject `state`). UI-обвязка (кнопки ветвей уже в HUD) — модалка/тосты Этап 12.
3. **fm() — только истощение.** Проверено по бандлу: `fm` потребляется в цепи истощения жил (@264622) и UI-тултипе (@76762); в `ce()` (доход) её НЕТ — аудит §branches (power_L0 = 14+4 ровно) это подтверждает. Порт: `production.sleepFor` (per-планетный хук); в `incomeContext` fm НЕ прокидывается (баг первой интеграции — исправлен тестами GS-16).
4. **Авто-surge: шаг тикера вместо setInterval.** 1.x v0.0.39.0 — планировщик `setInterval(2000)` c guard `window.__voroniaSurgeSchedulerV0390`; 2.0 — проверка порога `surgeNextAt` каждый тик (после production, до computeIncome). Семантика эквивалентна (nextAt rand 45..120с/90..240с, dur 20/25с, pct .0195/.092, без науки/сонара, кулдаун клетки = surgeUntil). Тост-троттлинг 12с — UI Этап 12.
5. **Детерминизм вместо Math.random.** Surge-рандом и ролл мутанта (12%, type3 И type5) в 1.x — `Math.random()`; в 2.0 — сидированный rng: `rng.fork('surge:'+gameMs)` и exploration-rng. Осознанная девиация (порядок значений тот же, конкретные последовательности — нет; критерий ТЗ — детерминизм по seed).
6. **Синтез через единый ledger c scope-меткой.** 1.x хранит запасы per-planet (Me/At) и списывает вход из хранилища планеты; 2.0 срез — глобальный `ResourceLedger` c `scope: planet:<pid>` в транзакции (reason `synth:<pid>`). Полноценные пер-планетные стоки — Этап 9 (см. TV-25). `Ay` (offline-тик, offlineCapMult) — Этап 11 (TV-31).
7. **Locked-логика ti() дословно.** продукт/вход проверяются через `Kt` (RESOURCE_UNLOCK): carbon→`unlock_carbon`, kriogen→`unlock_kriogenBoost`; krios требует ОБА (вход kriogen). anomalies-счётчик в статусе сохраняется и при locked (аудит ti_noAnomaliesExplored).
8. **ucm-асимметрия tl() портирована дословно.** Энергия deep-конверсии — round(4000) БЕЗ ×ucm, материал — round(500×ucm) (ferrum «Мёрзлый» 1.2 → 4800⚡/600⛏). Баг 1.x сохранён как факт (метод: никаких выдуманных «исправлений»).
9. **Наука разряда — через ledger.** `tryCommit({research:+g})` (аудит: +5/+15×mult; кap-цепь ng не затрагивается — разряд вне планетного research-капа; глобальный research-буст ×(1+sciencePct) — в computeIncome).
10. **Баффы зарядов не персистятся.** `n.chargeBuffs` в 1.x — runtime-состояние (пропадает при перезагрузке); 2.0 — так же: `charge.reset()` в applyState, в save v2 полей нет (TV-32; расширение схемы — при необходимости на Этапе 6). Персистятся только клеточные поля (`chargedEver`, `tO`/cooldown — часть SerializedCellState, как в 1.x v39).
11. **Чистые функции ветвей — в contracts.** `branchOf`/`isAnomalyBranch` живут в `contracts/anomalies.ts` (потребители: economy/synth, planets/anomalies) — иначе R2 (economy ↛ planets). `fmFor`/`AnomalyService` — в `planets/anomalies.ts`.
12. **Хуки поздних этапов — явные плейсхолдеры.** `spcHiddenFor` (spc_hidden, Этап 7, TV-29), `roleMultFor`/`modsFor` (Co/mt, Этап 9, TV-30), `chargeEnergy`/`chargeScience` (подключены), `sleep` (в income — только глобальный хук, по умолчанию 1).

## Альтернативы (отклонены)

- **Дословный setInterval-surge:** ломает детерминизм и headless-тесты; шаг тикера покрывает семантику (решение 4).
- **Per-planet стоки синтеза сразу:** тянет транспорт/склады Этапа 9 в срез Этапа 4; scope-метка даёт миграцию без изменения формул (решение 6).
- **«Исправление» ucm-асимметрии:** нарушает метод паритета (решение 8).
