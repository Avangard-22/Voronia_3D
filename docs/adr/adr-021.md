# ADR-021 · Этап 9.3 — дерево технологий, реактор/крафт и фикс миграции кулдаунов

**Статус:** принят (2026-11-03). **Драйвер:** ТЗ Этап 7 («Технологии и мета»:
граф prerequisites/cost/effects/unlocks, эффекты — типизированные модификаторы,
каждый unlock тестируется) и Этап 8 («Реактор и крафт»: явный выбор рецепта,
дефицит, время, состояние; ТЗ §6 — «Реактор в покое…», атомарность списаний,
персистентность очереди, UI не «прыгает»), плюс баг со скриншота владельца:
карточки показывали «⏳ 1700000000 с» — эпохальные миллисекунды в игровом кулдауне.

## Решения

1. **Дерево поверх данных v1, недостающий баланс — одним блоком политики.**
   Многоступенчатые технологии (`costScale, ironBoost, maxLevel, crystalBoost,
   kriogenBoost, therm, hyperdrill, recon`) берут цены из `registry.tech.costScaleTable`
   (строки v0.0.41, ключи `e/i/k/c` → ledger-ключи) с поздним ростом
   `costCurveLate.lateGrowth = 1.35` за уровнем после последней строки — parity 1.x.
   Имена unlock-исследований — из фикстуры `resources_research_v0.0.41.json`
   (`RESEARCH_NAMES`). Чего v1 в registry не оставила (цены unlock-исследований,
   численные эффекты) — собрано в единственном константном блоке `RESEARCH_POLICY`
   (`src/progression/techTree.ts`), как `ROUTE_POLICY`/`STAR_MAP_POLICY` ранее
   (ТЗ §15: баланс только через config/политику; миграция в registry — Этап 9.1 backlog).

2. **Эффекты — типизированные модификаторы на порте, а не строковые бонусы.**
   `TechPort` расширен пятью методами: `yieldMult('iron'|'crystal'|'kriogen')`,
   `veinCooldownMult()`, `veinYieldMult()`, `scanCostMult()`, `cellMaxLevelBonus()`
   (+ `level(id)`). Экономика потребляет их в существующих точках: факторы жил и
   агрегаторы дохода (`income.ts` — `boost`/`hyperdrill`), кулдаун жил
   (`production.ts`), потолок уровня клетки (`upgrades.ts`), цена скана
   (`scanPricing.ts`). Никаких новых сущностей «в обход» доменов.

3. **`buyTech` — атомарная транзакция ledger.** Проверки в `TechState.canResearch`
   (unknown-tech → locked → max), цена `researchCost(section, id, level)`, списание
   одним `tryCommit` (reason `tech:<id>`), затем `applyResearch` (+1 уровень;
   для ключей v1 `TechLevels` — зеркало в legacy-хранилище, чтобы `costScaleMult()`
   продолжал работать как 1.x `Gk()`). Отказы: `unknown-tech | locked | max | cost`.

4. **Реактор (`src/crafting/reactor.ts`) — правила списания ТЗ §6.**
   Рецепты/слоты/лимиты — `registry.craft` v0.0.41 (11 рецептов, `baseSlots 1`,
   `queueCapBase 50`, `minTimeSec 5`); гейты рецептов — исследования дерева
   (`RECIPE_GATE`: `recipe_*`, `unlock_synth_*`). Входы run списываются ОДНОЙ
   транзакцией в момент старта run; нехватка → состояние `deficit` (пауза без
   потери прогресса, флаг на задаче, а не догадка по `paidForCurrent`); выход —
   одна транзакция `reactor:output` по завершении; отмена возвращает только не
   стартовавшие run (оплаченный текущий run невозвратен — как в 1.x). Время —
   игровое (`gameMs`); офлайн-прогресс реактора сознательно отложен на Этап 11.

5. **View-типы реактора и дерева — в контрактах.** `contracts/crafting.ts`
   (`ReactorView/ReactorJobView/ReactorRecipeView/ReactorSave`) и `TechNodeView`
   в `contracts/tech.ts`: snapshot/UI зависят только от contracts (прецедент
   `SynthStatus`). Следствие R2 (crafting не импортирует progression): причина
   отказа `locked:<researchId>` несёт id, а человекочитаемое имя UI берёт из
   снапшота `tech.nodes`.

6. **Фикс миграции кулдаунов — `legacyGameMs()` в `schema.ts`.** Legacy v39 писал
   в `cooldownUntil` как игровые мс, так и epoch-мс (`Date.now()`-шкала). Значение
   `> 1e11` (заведомо больше любых игровых мс — ~3 года непрерывной игры) → 0;
   отрицательные/нечисловые → 0; остальные сохраняются. Это убирает «⏳ 1700000000 с»
   на клетках после импорта старого сейва.

7. **Персистентность очереди.** `SaveGameV2.reactor?` — опциональное поле
   (сейвы до 9.3 загружаются как обычно): задачи `{id, recipeId, runs, done,
   progressMs, paidForCurrent, deficit}` + `nextJobId`. `hydrate` отбрасывает
   задачи неизвестных рецептов и завершённые. `newGame` очищает очередь.

8. **UI: панели в колонке HUD, без карточек снизу (подтверждение курса 9.2).**
   «🔬 Технологии» — узлы дерева с уровнем/ценой/требованиями и кнопкой покупки
   (`data-act="buy-tech"`); «🏭 Реактор» — очередь (прогресс-бар, ETA в секундах
   run, подсветка дефицита, отмена) и рецепты (+1/+10). Пустая очередь — точный
   текст ТЗ «Реактор в покое…». Состав панелей не зависит от состояния очереди —
   структура не «прыгает» (ТЗ §6).

## Последствия

- 54 новых теста (26 дерево/команды/модификаторы, 23 реактор/UI, 5 миграция);
  каждый `RESOURCE_UNLOCK`-unlock проверяется индивидуально (Этап 7 ТЗ).
- `REJECT_REASONS` расширен (`locked, unknown-tech, unknown-recipe, queue-full,
  unknown-job`) — аддитивно, существующие потребители не затронуты.
- `GameSnapshot` получил обязательные поля `tech`/`reactor` — все производители
  снапшота в репозитории одни (Game), тесты прошли.
- Открыто: prestige-матрица (Этап 7 ТЗ, частично), офлайн-прогресс реактора
  (Этап 11), перенос `RESEARCH_POLICY` в registry (Этап 9.1).
