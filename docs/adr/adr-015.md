# ADR-015: Порт генератора планет 1:1 (Этап 3)

**Статус:** ПРИНЯТО

## Контекст

Критерии Этапа 3 (README): генератор планет по seed, сид-детерминизм, биомы/дескрипторы/роли/рукава, геометрия (тюнинг), krios + генерируемые планеты, паритет с задокументированными фактами. В 1.x генератор — класс `or` (@81832) и функции Jc/Zc/Jo/Qc/Rf/Lf/Bf/Of/VorResRoll/VorCrystalEnsure/ni/Dy/Br/My/er/Kf/Yf, рассеянные по бандлу и завязанные на глобальное состояние (`ge.PlanetaryGraph`, `$` PLANETS, `n.settings`, `BAL`).

## Решение

1. **Байт-паритет вместо «свободной» реализации.** Все функции портированы дословно: те же mulberry32-соли (XOR-константы), тот же порядок потребления RNG, та же арифметика (включая сохранённые особенности 1.x: `toFixed(7)`-дедуп вершин, `%b.length`-страховку в research-ролле, raw-push ребра в fallback Kf в обход cap, равномерные twin/noise-деформации, гасимые нормализацией). Любое «улучшение» ломает фикстуры — запрещены без явного решения владельца.
2. **RNG — `mulberry32` в contracts/rng.ts** (слой 0): 1.x `qe` совпадает с ним байт-в-байт, поэтому домены берут его напрямую, а не через `RngPort` (тот — для сейв-состояния 2.0 с fork/hydrate). Исключение GS «gameStartSeed» (последовательности 2.0 ≠ 1.x) касается только глобального Rng игры, не генератора.
3. **Чистые функции + мутабельный объект планеты.** `GeneratedPlanet` (contracts/planets.ts) повторяет форму экземпляра `or` (мутабельные клетки/поля, Set с порядком вставки). Методы 1.x стали функциями (`buildPlanet`, `assignPlanetResources`, `applyMixedClusters`, `initPlanetStart`) — состояние передаётся первым аргументом.
4. **Разделение доменов (R2):** planets владеет генератором; galaxy — позицией (`Br/My/er`), таблицей рукавов (из baseline) и графом (`Kf/Us/Hs/Jn`); оркестрация `discoverPlanet` (порядок: build → позиция/armId → assignResources → initStart → ni → assignResources) — в `core/discovery.ts` (composition root). Награда `floor(500×2.2^max(0,idx−2))🔬` возвращается числом; начисление через ledger — за Game.
5. **Зависимости инжектируются через `GeneratorCtx`** {balance, arms, uniqueForms?, veinProfile?}: `veinProfile` (1.x Vr) живёт в economy — planets не импортирует его (подставляет core); в потоке генерации уровни всегда 0 → {1,1}.
6. **Данные — только извлечение.** Статические таблицы бандла (Nn/Ar/$f/If/Cf/Tf/Af/Qa/Dy, xf/kf/uy) — `src/planets/tables.ts`, сгенерирован из fixtures/planetgen_tables.json + дословных дампов; баланс-значения (resourceDist, geometryTuning, galaxy.gen/arms/nodeRender, events.polarityWeights, roles.defs, lastVoronia) — registry.json через типизированный RegistryView. Таблица ресурсов `te` (rare/minPlanetIndex/hidden/legacy) — contracts/resources.ts `RESOURCE_GEN` (порядок ключей значим: for-in в 1.x).
7. **settings.uniqueForms по умолчанию true** (дефолт 1.x подтверждён: unique-планеты в фикстуре деформированы — ring/split меняют геометрию, twin/noise нет).
8. **Паритет-тесты** (tests/planetGenerator.test.ts, 16): 6 full-dump сэмплов (клетки/verts/полигоны/palette/lore/события/узел графа), расширенная фикстура planetgen_named_v0.0.41.json (новый экстракт: авто-имена Rf/Af — сэмплы Этапа 0 создавались с именем «Ген-Тест» и Rf не покрывали; позиции Br для planet_04+; unique-миры; lastVoronia idx15; barren; рёбра Kf), krios (92 клетки, TV-11) и ferrum (GS-02) из oi(), детерминизм, тюнинг геометрии.

## Альтернативы

- «Чистая» реimplementation по описанию механик — отвергнута: ТЗ запрещает выдуманные формулы, а паритет спасений (schema 39 хранит seed/f/geometry и ожидает идентичный мир при deserialize) требует байт-точности.
- Класс `Planet` с методами — отвергнут: домены 2.0 функциональные (runtime.ts, ledger.ts), класс затрудняет инжекцию ctx и сериализацию.
- Генератор в galaxy-домене — отвергнут: planeta владеет клетками/биомами; galaxy даёт только позицию/рукав/граф.

## Последствия

- Deserialize mixed-миров (`_forcedClusters`) портирован, но не покрыт фикстурой (TV-26, Этап 11).
- Сонар-превью (Zn) обязан переиспользовать rollResources/crystalEnsure (TV-27, Этап 6).
- Роли: данные типизированы (registry roles.defs), назначение — механика transport/UI (TV-28).
- Js/jr (рендер-кэши клеток/звёзды) не портированы намеренно — данные планеты не меняют; появятся в renderer-домене.
