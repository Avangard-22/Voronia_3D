# ADR-017 — Этап 5: world-состояние в Game, реплей спеков открытия, границы 3D-прототипа

**Дата:** 2026-11-02 · **Статус:** принят · **Контекст:** подключение `core/discovery.ts` к Game (команды `discoverPlanet`/`setActivePlanet`), доход type7 (TV-24), 3D-прототип renderer (вердикт R1). Аудит: `fixtures/stage5_audit_v0.0.41.json` (tools/extract_stage5.cjs).

## Решения

1. **Мир живёт в Game, не в каталоге.** Каталог — статический срез v0.0.41 (ferrum/krios/именованные); 1.x `$` (planets) + `ge.PlanetaryGraph` — динамические. В 2.0 Game владеет `world: DiscoveryWorld` (createStarterWorld: ferrum+krios, Fr=2 — аудит §discover.before) и графом; открытие добавляет GeneratedPlanet в world и PlanetRuntime в runtimes. `worldPlanet(pid)`/`galaxyGraph()` — публичные аксессоры для renderer/UI.
2. **Персистенция открытий — реплей спеков, не дамп планет.** 1.x v39 хранит полные планеты; 2.0 save v2 хранит `discoveredSpecs` (id/name/seed/f/geometry/biome/planetIndex) и детерминированно воспроизводит миры при загрузке (buildPlanet/Yf/initStart/ni — чистые функции от seed+порядка; тест save-roundtrip: узел/рукав/рёбра совпадают). Порядок спеков = порядок открытий (критично: Fr-счётчик и generatePosition зависят от существующих узлов).
3. **Награда за открытие — через ledger.** 1.x: `n.research += g` напрямую + тост; 2.0: атомарная транзакция `discover:<pid>` (ADR-013: баланс только через ledger). Сумма дословно: floor(500×2.2^max(0,idx−2)).
4. **Без автосмены активной планеты.** Аудит §discover.afterFirst.activePlanetId='ferrum' — открытие не переключает; переключение — отдельная команда `setActivePlanet` (guard «существует И открыта», иначе reject `state`; krios до сонар-открытия — locked, TV-33).
5. **Historical deferral, superseded by Phase 10.1.4:** planet storage On/yy was initially postponed. It is now restored: `iron`, `kriogen`, and `extraResources` are stored per planet and swapped atomically on active-planet changes. UI fields (selectedCellId/planetPage/rotX/rotY) remain renderer/HUD state.
6. **type7 — в общей энерго-группе c двумя отличиями.** (а) `Ws` (deepMult=2) умножается ВСЕГДА, независимо от isDeep клетки (аудит §type7.deepInvariance); (б) отдельная кристальная линия crystalRate×цепь×coreEffect. Новый хук `coreEffect` (1.x mt(pid,'coreEffectMult')) — плейсхолдер=1. Ur(7)=100 без _memberCount.
7. **Renderer: чистый билдер + тонкая WebGL-обвязка.** `planetMesh.ts` (данные → типизированные массивы; детерминирован, тестируется в node) отделён от `scene.ts` (Three.js/DOM — не тестируется headless, смоук-импорт). Импорт `three` разрешён ТОЛЬКО домену renderer (allowlist check_arch) — локализация зависимости (ТЗ: замена рендерера не должна задевать домены).
8. **Объём 3D-прототипа — по вердикту R1, не по baseline-визуалу.** Поли-сетка клеток (poly из Nn/_sortPoly-порта Этапа 3) + граф соседства + маркеры InstancedMesh в THREE.LOD (2 уровня) + drag-вращение + FpsMeter (fps/avg/p95, окно 240). Эффекты/частицы/2.5D-оверлеи baseline — Этапы 6/12 (статус домена PARTIAL). Замер на целевом Android — TV-36 (в песочнице недоступен).
9. **Открытие krios — НЕ Этап 5.** Аудит бандла: krios открывается сонар-миниигрой (Q1 @251512: unlockedPlanets.add('krios'), node.discovered=true, scanBonus {mult,until,accuracy}) — Этап 6 (TV-33). В тестах Этапа 4 krios открывался save-циклом — временно, до сонара.

## Альтернативы (отклонены)

- **Полный дамп планет в сейве (как 1.x v39):** ~100 КБ+ на мир, дублирование детерминированного генератора; реплей спеков меньше и проверяем (решение 2). Риск: смена алгоритма генератора сломает старые сейвы — фиксируем версию баланса/генератора (v0.0.41).
- **Автопереключение на открытую планету:** противоречит аудиту (решение 4).
- **Своп storage сейчас:** тянет пер-планетные стоки/склады в Этап 5 (решение 5).
