# Stage 7.4 — Planetary System Exploration

## Реализовано

1. Добавлена чистая модель `buildStarSystemExploration()` в `src/renderer/galaxySystemExploration.ts`. Она строится только из обнаруженного узла `PlanetaryGraph` и соответствующего профиля звезды Stage 7.3.
2. Карточка системы теперь содержит список подтверждённых миров с названием, биомом, геометрией, состоянием открытия и признаком активной планеты.
3. Скрытые узлы не попадают в модель системы; закрытый мир можно видеть как обнаруженный, но нельзя посетить.
4. Для активной системы добавлена команда перехода к поверхности. Для другой открытой планеты перелёт выполняется через существующий `Game.dispatch('travelToPlanet', ...)`; после успешной доменной операции интерфейс автоматически переключается на планетарную сцену.
5. Возврат к галактике остаётся через переключатель сцен. Экономика, маршруты, активная планета и сохранение продолжают использовать существующие доменные механизмы.
6. Добавлены тесты `tests/stage7_4_system_exploration.test.ts`.

## Архитектурное ограничение (важно)

Текущий `PlanetaryGraph` моделирует каждый планетарный узел как отдельную систему и не содержит отношения «одна звезда — несколько планет». Поэтому эта версия показывает только реально подтверждённую планету, связанную с выбранным узлом. Дополнительные планеты, орбиты и спутники не генерируются как фиктивные игровые объекты. Для полноценной многопланетной системы понадобится отдельная доменная сущность `StarSystem`, каталог `SystemBody`, орбитальное исследование, генерация planet runtime и миграция формата сохранения. Это следующий самостоятельный слой, а не косметическое дополнение рендера.

## Продолжение Stage 7.4 — доменный каталог орбитальных тел

Выполнен следующий подэтап: добавлен `src/galaxy/starSystems.ts` — детерминированная доменная генерация каталога звёздной системы от `GraphNode.seed`.

- Для обнаруженного узла формируется стабильный профиль звезды (класс, температура, светимость).
- Первый объект каталога связан с существующей игровой планетой и её `planetId`.
- Дополнительно формируются 1–3 орбитальных кандидата с параметрами орбиты и классом тела.
- Кандидаты имеют статус `unscanned`, не получают имя и `sourcePlanetId`; UI-проекция не раскрывает класс/состав.
- Каталог проверяется `validateStarSystemCatalog()` на корректность орбит, уникальность ID, связь с host и отсутствие утечки личности неразведанных тел.
- UI карточки системы показывает число неразведанных орбит и их условное положение. Посещение/сканирование кандидатов пока не доступно: для этого потребуется доменная команда исследования орбиты, создание runtime только для тела класса planet и миграция сохранения.
- Генерация чистая и воспроизводимая из seed, поэтому дополнительное состояние сохранения на данном подэтапе не требуется.
